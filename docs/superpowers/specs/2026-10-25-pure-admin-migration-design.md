# 矿山视界 Pure Admin 精简版前端升级设计

日期：2026-10-25  
状态：已在 `pure-admin-upgrade` 分支实施首期迁移；验收记录见实施计划  
已确认：采用 Pure Admin 精简版；告警大屏采用系统内统计页加一键全屏。

## 1. 目标与边界

将现有原生控制台迁移到 Vue 3，统一导航、表单、监控画面与告警展示。迁移完成后，现有真实 USB 摄像头可以继续通过普通视频导入流程管理，模型、参数、区域和历史告警均可延续。

首期继续面向 Windows 本机使用，中文界面。保留 Python、YOLO、OpenCV、FFmpeg、MediaMTX 和 SQLite。浏览器换页、刷新或全屏不得触发分析进程重启。

不引入新的业务后端、多租户、用户权限平台、云端部署、WebRTC 转码服务、拖拽大屏编辑器或告警处置工作流。模板登录页不是服务端身份认证；本期沿用本机访问限制，不展示虚假的登录保护。

## 3. 迁移方式选择

| 方式 | 收益 | 代价 | 选择 |
|---|---|---|---|
| 同一 Python 服务下新旧入口并行，逐页迁移 | 可对照相同数据，方便退回旧界面 | 临时维护两个入口 | 推荐 |
| 一次性替换全部界面 | 过渡代码少 | 导入、布控、监控和大屏问题集中暴露 | 不采用 |
| Vue 独立长期部署并新增网关 | 可独立运维 | 增加端口、认证、部署复杂度 | 当前不需要 |

建议采用官方非国际化精简版。在实施开始时选择一个验证通过的上游提交，记录提交号、Node 和包管理器要求，保留许可证和锁文件。不要持续跟随浮动的 main 分支自动升级。

## 4. 页面结构与交互

保留现有五个业务入口，不增加空白管理模块：

| 页面 | 主要内容 | 迁移要求 |
|---|---|---|
| 视频管理 | 摄像头卡片、状态、添加、编辑、启停、删除 | 统一 USB 和 RTSP 导入，保留设备关联 |
| 实时监控 | 单画面及多画面、场景选择、检测框和区域 | 单台默认单画面；无虚构摄像头 |
| 告警大屏 | 指标、趋势、类型分布、摄像头排行、最近证据 | 复用真实统计接口；普通模式与全屏共用数据 |
| 场景模型 | 现有场景、模型说明与关联配置入口 | 不扩展为新的模型训练或上传平台 |
| 事件记录 | 条件筛选、分页、证据查看、导出 | 承接大屏筛选条件，不只过滤最近 100 条 |

视频导入继续采用四步：视频接入 → 场景选择 → 参数配置 → 区域布控。USB 设备发现作为第一步内的“本机设备”来源选项，准备成功后得到普通 RTSP 地址并进入相同后续步骤，不单独建设 USB 管理页面。

默认保持现有深色、青绿色风格，使用 Pure Admin 的导航和 Element Plus 控件统一间距、表单与反馈。告警使用琥珀色，故障使用红色，同时展示状态文字。默认进入视频管理，不新增与告警大屏重复的工作台。

页面布局：左侧导航，顶部面包屑与服务连接状态，主体为当前页面。监控和大屏优先分配给内容区域，不在每个页面重复全站指标卡。

桌面验收尺寸为 1920×1080 和 1366×768；较小窗口允许滚动。移动端只保证基础可访问，不作为首期区域编辑的主要操作环境。

## 5. 工程与部署设计

新增 `frontend/` 存放 Pure Admin 工程，业务页面放在 `src/views/`，按视频、监控、大屏、模型和事件分目录。使用模板已有路由、请求封装和状态管理，不重复引入另一套基础设施。

只提取确实跨页复用的业务组件：

- 摄像头编辑器：四步配置和待保存草稿。
- 画面组件：原图、同帧检测框、区域及加载状态。
- 区域编辑器：坐标变换、绘制、拖动和删除。
- 证据查看器：不可变告警记录与对应截图。
- 图表组件：优先复用既有 SVG 计算与绘制逻辑，封装为 Vue 组件；首版三类基础图表不额外引入 ECharts，后续复杂交互再评估。

构建输出到 `frontend/dist/`。开发时使用 Vite；交付时只需要 Python 服务和构建产物，用户不需要常驻 Node 进程或额外终端窗口。

过渡期：旧页面继续在 `/`，Vue 页面通过 `/ui/` 进入。Vue 使用 `/ui/` 资源基路径和 Hash 路由，例如 `/ui/#/cameras`，避免给 Python 增加复杂的前端路由回退逻辑。

最终：验收后将 `/` 重定向到 `/ui/`，旧页面暂保留在 `/legacy/`。旧版根路径资源继续可用。退回时只恢复首页路由，不能回滚数据库或覆盖摄像头配置。过渡期仅打开一套界面进行写操作，避免两个页面编辑同一摄像头。

Python 新增静态资源处理仅允许访问 `frontend/dist/` 内文件；校验解析后的实际路径，防止越界读取；正确返回 MIME。未知静态资源返回 404，不能用 HTML 掩盖资源缺失。入口文件不缓存，带内容哈希的资源可长期缓存。API、图片证据和预览路由保持现有语义。

图标、字体、依赖和样式全部打入本地制品，禁用 CDN 替换和远程图标请求。没有完成构建时保留旧入口并给出明确提示，不自动下载依赖。

## 6. 接口兼容与本机请求校验

前端适配现有 JSON 结构，不为了模板统一响应包装而批量修改后端接口。

| 用途 | 现有接口 |
|---|---|
| 初始化、摄像头和分析状态、令牌 | `GET /api/state` |
| 枚举设备、准备本机视频源 | `GET /api/cameras/devices`、`POST /api/cameras/live/prepare` |
| 地址探测、配置保存 | `POST /api/cameras/probe`、`POST /api/cameras/save` |
| 分析启停、删除 | `POST /api/cameras/start`、`/stop`、`/delete` |
| 告警统计、分页和导出 | `GET /api/alerts/dashboard`、`/query`、`/export.csv` |
| 图片、证据和素材预览 | `/covers/`、`/media/`、`/evidence/`、`/preview/` |

状态初始化成功前，禁止提交配置。令牌只保存在内存，写请求附带 `X-Console-Token`，不使用模板模拟账号、模拟菜单和模拟刷新令牌。

服务重启导致令牌失效时重新获取状态并提示用户重试操作，不自动重放启停、保存或删除请求。请求超时不表示写入一定失败，应重新获取状态核对。

开发代理转发 API 和上述媒体路径到 `127.0.0.1:8765`。由于后端同时验证 Host 与 Origin，不能只配置 changeOrigin：受控的本机开发代理须将转发 Host、Origin 都调整为目标本机服务地址；Vite 仅绑定回环地址，不取消后端校验或开放任意跨域。生产环境始终同源。

## 7. 摄像头与画面的关键兼容点

1. 保留 `coverToken` 验证流程；设备身份继续由后端探测映射确定，不信任前端提交的设备身份。
2. 编辑时地址未变应保留原有设备关联；切换地址按现有规则清理，不能静默把 USB 视频变成失去关联的普通条目。
3. 保存配置与启动分析是独立动作，页面挂载和刷新不能自动启动、停止或重建推流服务。
4. 页面轮询不能覆盖正在编辑的表单草稿；离开未保存编辑器需要明确提示。
5. 区域继续采用现有归一化坐标。按实际图像内容区域换算坐标，排除 object-fit 留白；缩放和全屏后坐标必须保持一致。
6. 检测框与截图作为同一结果整体更新，避免新框叠到旧帧上；切换摄像头后丢弃上一设备的迟到图片和请求。
7. 复用现有预览能力：支持的本地视频走 `/preview/`，分析画面按现有图片与检测结果展示。RTSP 地址不直接赋给浏览器 video 元素，不把前端迁移扩展成新转码项目。
8. 明确区分未开始分析、运行、重连、故障与服务不可达，不把未启动统一标为设备离线。

## 8. 状态刷新与错误处理

应用只有一个状态轮询拥有者，先沿用现有约 1.5 秒节奏，完成上次请求后再调度下一次，避免并发堆积。普通状态与大屏聚合请求分开管理。

告警大屏默认 10 秒刷新；离页停止，隐藏标签暂停，恢复可见时立即刷新。路由卸载或停用时取消页面请求、定时器、事件监听和图表观察器。监控与大屏首期不使用会保留后台轮询的页面缓存。

筛选变化取消旧请求，并用请求序号防止旧响应覆盖。失败时保留最近成功的数据，标明更新时间和未更新状态；首次加载失败显示错误，不能显示假零值。

全屏容器包括图表和证据弹窗。Element Plus 弹窗的挂载目标必须放入该容器，不能默认传送到全屏元素之外。监听全屏变化，Esc 退出后筛选保留；全屏被拒绝时普通页面仍可使用。

## 9. 告警数据口径

复用已有大屏设计与当前后端实现，迁移前核对两者差异。保留五个指标、三类图表、最近告警及当前分析状态。

时间使用 UTC+8 的站点口径，查询为半开区间 `[from,to)`，最长 90 天。图表、明细和导出共享实际起止时间及筛选条件；自定义范围不随刷新移动。

告警总数基于真实事件记录，不是人数，也不是最近 100 条长度。普通人员检测不产生报警时显示正常空状态；不自动替主人启用区域入侵规则。发送队列状态不映射为业务处理状态，不引入无数据来源的安全评分。

本次前端迁移不新增数据库迁移。当前大屏代码已有的索引初始化应作为前置基线单独验证，不以“换前端”为理由重建数据库。

## 10. 分阶段实施与验收

| 阶段 | 交付内容 | 通过条件 |
|---|---|---|
| 0 基线固定 | 核对未提交大屏改动、接口样例和测试，记录上游版本 | 明确哪些现有行为已经通过验证；不覆盖本机数据 |
| 1 前端基础 | Pure Admin、五项导航、请求适配、双入口、本地构建 | `/ui/` 可离线加载；读写令牌校验有效；旧入口仍可使用 |
| 2 摄像头与监控 | 四步编辑器、设备接入、启停、画面和区域编辑 | 当前真实摄像头可读取和编辑；同地址保存保留设备身份；旧配置无损回显 |
| 3 告警迁移 | 大屏、全屏、事件分页、证据和导出、模型页面 | 统计口径一致；全屏可查看证据；筛选快速切换无数据串页 |
| 4 回归与切换 | 完整构建、回归、长期运行、默认入口切换 | 全部门槛通过后切换；旧入口可退回 |

测试必须覆盖：

- 前端类型检查、构建和当前后端相关测试；实施时根据模板 scripts 确定实际命令并记录。
- 接口适配：初始化失败、403、超时、令牌刷新、错误返回；写请求不被自动重试。
- 区域坐标：不同画面比例、留白、窗口缩放、全屏和保存再打开。
- 摄像头流程：真实设备发现、RTSP 准备、保存、编辑及身份保持；启停测试在用户安排的验证时段执行，避免意外打断现有分析。
- 告警统计：超过 100 条隔离测试数据、时间边界、筛选与导出一致、无告警和证据缺失。
- 浏览器流程：页面刷新、路由切换、全屏 Esc、弹窗、断开后端后的恢复和离线资源加载。
- 30 分钟监控与大屏运行，并切换页面至少 50 次；单类轮询不累积、监听和观察器可释放、无持续内存增长趋势，不触发额外分析进程。
- 保留现有大屏性能目标：在当前机器用隔离的 10 万条记录测常见 30 天查询，P95 目标不超过 1 秒。记录实测结果，不把目标当作已达成。

每阶段只提交相关源码和必要构建配置，不纳入真实数据库、摄像头配置、运行日志或临时脚本。第一阶段完成后即可评审整体外观；第二阶段通过后再扩大迁移范围。

## 11. 风险与回退

最高风险是设备身份丢失、区域坐标偏移、重复轮询、图片与检测框错帧以及开发代理校验失败，均已列入验收。

切换默认入口前保存旧前端和已验证构建产物，并记录构建版本。前端异常时恢复首页指向旧界面；业务数据保持原样。旧页面停用前保留一个完整验收周期，删除旧代码作为后续独立变更。

本方案不会直接改善摄像头采集断流；发现采集稳定性问题应按原视频链路单独定位。

## 12. 设计结论

采用 Pure Admin 非国际化精简版，同服务双入口过渡，先完成真实摄像头管理与监控，再迁移已存在的告警大屏和事件记录。最终交付仍保持本机无窗口启动和离线运行方式。

本文件只定义升级方案，不代表已安装模板、迁移代码、运行测试或完成发布。
