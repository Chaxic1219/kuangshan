# 告警数据大屏升级方案

日期：2026-10-25  
基线：`6ab9a46`  
状态：设计提案，待主人确认；尚未实施  
已确认方向：系统内统计页＋一键全屏

## 1. 升级目标

在现有控制台侧栏增加“告警大屏”，回答四个问题：选定时段发生了多少告警、哪些类型最多、哪些摄像头最集中、最近发生了什么。

普通模式供日常查看、筛选和查看证据；全屏模式供监控室展示。两种模式使用同一页面、同一数据和同一筛选条件，避免出现两套统计口径。

首版不修改摄像头采集、推理、跟踪、报警冷却和告警上报流程，不自动为现有摄像头启用新报警场景。

## 2. 当前系统具备的基础与缺口

### 已具备

- Python 本地控制台、原生 JavaScript/CSS 页面及 SVG 画面叠加能力。
- SQLite `events.db` 中的 `alerts(id, camera, at, record)` 持久化告警记录。
- 告警编号、事件类型、摄像头编号和名称、发生时间、检测框及截图证据。
- 人员区域入侵、车辆区域入侵、未戴安全帽、未穿反光衣、火焰、烟雾、亮度异常等报警场景。
- 摄像头分析状态、证据查看及 CSV 导出。

### 必须明确的边界

1. 当前 `/api/state` 只返回最近 100 条告警。大屏统计必须从数据库按时间范围聚合，不能在这 100 条上计算趋势或占比。
2. 普通人员、车辆检测的 `alarm=False`，不会写入告警表。当前真实 USB 摄像头仅启用了人员检测，因此即使检测到人，也不应增加大屏告警数。
3. 一条本地告警记录可能包含多个目标。一条记录计为一次“告警事件”，不能称为人数、违规人数或事故次数。
4. outbox 的 pending/dead 描述发送队列，不是业务处理状态。现有本地数据没有完整的确认、处置、误报审核流程。
5. 现有导出及上报风险等级主要按检测引擎粗分，不能据此构造可信的“高危占比”或“安全评分”。首版不展示风险等级图。
6. 告警数受分析是否运行、场景启用情况和冷却时间影响。告警减少不能直接解释为安全改善。

## 3. 方案选择

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 现有控制台增加统计页，并支持全屏 | 复用摄像头、数据库和证据页面，改动集中 | 需要独立统计接口和页面刷新控制 | 本期采用 |
| 独立部署一个大屏应用 | 可独立访问和扩展多终端 | 增加认证、接口部署和运行维护 | 当前没有必要 |
| 同时建设告警处置中心 | 可提供待处理、处理率、处理时长 | 需要状态流转、操作记录及业务规则 | 作为后续独立升级 |

## 4. 信息架构与布局

侧栏顺序建议：视频管理 → 实时监控 → 告警大屏 → 场景模型 → 事件记录。

以 1920×1080 为全屏主布局；普通桌面模式自适应窗口宽度。复用现有深色、青绿色视觉体系，以琥珀色强调告警信息，避免所有数字和边框都闪烁。

```text
┌───────────────────────────────────────────────────────────────────┐
│ 告警数据大屏   时间范围／摄像头／事件类型   更新时间   刷新  全屏  │
├─────────────┬─────────────┬─────────────┬─────────────┬─────────────┤
│ 告警事件总数│ 发生告警路数│ 告警类型数  │ 最多告警类型│ 最近告警时间│
├───────────────────────────────────────┬───────────────────────────┤
│ 告警数量趋势：小时／天                 │ 告警类型分布              │
│ 折线图                                │ 环形图＋数量、占比列表    │
├──────────────────────┬────────────────┴───────────────────────────┤
│ 摄像头告警排行       │ 最近告警：时间、类型、摄像头、证据缩略图   │
│ 横向条形图           │ 点击查看发生时的证据                       │
├──────────────────────┴────────────────────────────────────────────┤
│ 当前分析状态：运行中／重连中／故障／未运行；数据口径与更新时间     │
└───────────────────────────────────────────────────────────────────┘
```

### 指标与图表

| 模块 | 计算口径 | 用户操作 |
|---|---|---|
| 告警事件总数 | 选定范围、摄像头、事件类型下的有效告警记录数 | 跳转对应明细 |
| 发生告警路数 | 有告警记录的不同摄像头编号数 | 查看摄像头排行 |
| 告警类型数 | 非零的不同事件类型数 | 查看类型分布 |
| 最多告警类型 | 记录数最多的事件类型；并列时显示并列提示 | 筛选该类型 |
| 最近告警时间 | 当前筛选下最新一条告警发生时间 | 查看该条证据 |
| 数量趋势 | 按小时或天统计记录数，缺失时间桶补 0 | 点击时间桶筛选明细 |
| 类型分布 | 按事件类型计数，分母与总数一致 | 点击类别筛选，提供清除条件入口 |
| 摄像头排行 | 按摄像头编号聚合，显示前 10 路及其余路合计 | 点击某路筛选 |
| 最近告警 | 当前筛选下最近 20 条，时间倒序 | 查看截图与完整检测信息；进入分页明细 |
| 当前分析状态 | 所选摄像头的实时分析状态，不受历史时间筛选影响 | 跳转视频管理或实时监控 |

不添加地图、三维矿山、随机滚动数字或无数据来源的安全指数。当前只有一台真实摄像头时，排行正常显示一条，不填充虚构设备。

## 5. 筛选与时间口径

- 默认“今日”，同时提供最近 24 小时、近 7 天、近 30 天和自定义时间；首版单次查询最长 90 天。
- 时间区间统一为 `[from, to)`。自然日按站点时区切分，落库和查询边界转换为 UTC。
- 首版站点时区固定为 `Asia/Singapore`（UTC+8，与当前使用环境一致），前后端共用，避免浏览器所在时区改变统计结果。
- “近 7 天／近 30 天”分别包含今日及前 6／29 个自然日，截至本次查询时间；“最近 24 小时”为滚动区间。
- 不超过 48 小时采用小时桶，超过 48 小时采用自然日桶。
- 摄像头支持全部或单路，事件类型支持全部或单类。筛选条件全屏前后保持一致。
- 自定义时间范围固定不移动；相对时间范围随刷新更新。后端返回实际使用的起止时间，图表与明细使用相同边界。
- 总数、趋势合计、类型分布合计、完整摄像头分组合计必须相等。
- 历史告警按摄像头编号聚合；摄像头被删除或改名后，仍保留历史记录中的名称，不丢弃历史告警。筛选列表应包含有历史记录的已删除摄像头并标注状态。

## 6. 普通模式与全屏模式

普通模式保留导航、筛选和证据查看能力。点击“全屏”通过浏览器 Fullscreen API 展开大屏容器，隐藏侧栏和无关页面标题；退出全屏后恢复原布局。

- 全屏仍保留简洁的时间范围和退出入口，不自动改变用户筛选。
- 使用 `fullscreenchange` 同步界面，支持 Esc 退出；浏览器拒绝全屏时显示明确提示并保留普通模式。
- 证据弹窗必须位于全屏容器内，确保全屏时能看到；复用现有证据呈现逻辑。
- 1366×768 等较小窗口允许纵向滚动，禁止简单整体缩小到文字无法阅读。
- 图表图例和数值可读，颜色之外同时显示文字类别；关闭或减少动画时仍完整可用。

## 7. 数据与接口设计

### 7.1 统计接口

新增 `GET /api/alerts/dashboard`，参数为 `from`、`to`、`cameraId`、`eventId`。时间粒度由后端按范围决定。

返回内容：

- `generatedAt`、`timezone`、实际筛选范围、`bucket`。
- `summary`：事件总数、告警摄像头数、类型数、最多告警类型、最近告警时间。
- `trend`、`byType`、`byCamera`、`recent`。
- `excludedRecords`：损坏或必要字段无效、未纳入统计的记录数量。

所有统计通过一次只读事务获得一致快照。图表统计全部匹配记录，只有最近列表和排行限制返回条数。

### 7.2 明细接口

新增 `GET /api/alerts/query`，沿用相同筛选参数，追加 `page`、`pageSize`，每页最多 100 条，按发生时间和编号稳定排序。

点击图表后，事件记录页面携带相同筛选条件读取此接口，而不是继续过滤现有最近 100 条。保留原有未筛选浏览能力，避免影响其他页面。

筛选后的导出沿用同一查询条件；导出文件注明统计范围。不能出现屏幕显示某一天、导出却包含全部历史数据的情况。

### 7.3 数据库与索引

- 继续使用现有 `alerts` 表，不增加独立统计数据库和后台统计服务。
- 为 `at`、`(camera, at)` 添加幂等索引，缩小查询范围；事件类型从 `record.eventId` 提取。实施前确认当前 SQLite 的 JSON 函数可用性。
- 使用参数化 SQL，校验时间跨度、事件类型及分页上限。
- 有历史坏 JSON 时统计跳过并显示“部分记录未纳入统计”，不能整页失败，也不能默认为 0 条告警。
- 建索引前用 SQLite 原生备份保存现有数据库；不覆盖摄像头数据，不迁移或删除已有事件。
- 告警证据目前没有自动清理策略。本期不新增清理动作；历史统计上限不等于删除超过 90 天的数据。

## 8. 前端实现与刷新策略

新增 `alert_dashboard.py`、`alert-dashboard.js`、`alert-dashboard.css`，职责分别为查询聚合、页面交互和布局。`console.py` 只接路由，`console.js` 只接导航和页面生命周期，避免继续把所有图表逻辑堆进现有大文件。

首版只有折线、环形、横向条形三类基础图表，优先使用原生 SVG 实现，并提供数值列表，不新增图表框架。后续确需复杂图表或交互时再单独评估依赖。

- 进入页面立即查询，默认每 10 秒刷新统计；离开页面停止查询，浏览器标签隐藏时暂停自动刷新。
- 大屏不沿用现有 1.5 秒全页面重建模式，只更新变化的数据和图形；不要每次刷新重新播放入场动画。
- 筛选变化取消旧请求或用请求序号丢弃过时结果，确保慢响应不会覆盖新筛选。
- 图表点击只修改筛选，不更改原始告警；默认不做自动轮播，避免查看证据时内容跳动。
- 当前分析状态复用已有状态来源，但与历史统计分开标识，不能把“未开始分析”误标为“设备离线”。
- 若系统内置浏览器不支持全屏，普通布局和统计功能仍正常工作。

## 9. 空状态与故障状态

| 情况 | 展示方式 |
|---|---|
| 没有历史告警 | 显示 0 和“当前范围暂无告警”，空图表不制造数据 |
| 仅启用人员等非报警场景 | 提示“当前启用的是检测场景；如需告警可配置区域入侵等报警场景” |
| 统计请求失败 | 保留上次成功数据，显式标记“数据未更新”和成功更新时间，提供重试 |
| 首次加载失败 | 显示错误状态，不显示一组容易被误认为真实结果的 0 |
| 截图丢失 | 保留事件信息并显示“证据图片暂不可用” |
| 摄像头重连或分析故障 | 在当前分析状态区标注，不自动计入业务告警事件总数 |
| 未配置 Java 上报 | 本地告警统计仍可用；如展示上报状态，必须单独标为“发送队列” |

演示数据只允许进入明确标注的独立演示环境，不能写入正式告警数据库。

## 10. 实施顺序

1. **数据统计与回归测试**：实现范围查询、聚合、索引和分页；验证统计不受最近 100 条限制。
2. **系统内大屏页面**：接入导航、指标卡、三类图表、最近告警及当前分析状态。
3. **交互与全屏**：筛选联动、分页明细、证据弹窗、导出范围、全屏与窗口适配。
4. **验证与交付**：隔离数据验证、真实事件核对、性能与长时间刷新检查，更新说明后提交。

首版验收后，再决定是否另做告警处置中心：待确认／处理中／已处理／误报、操作记录、处理时长和处理率。这些指标必须先有真实业务状态，不能由发送成功状态推导。

## 11. 验收标准

1. 超过 100 条的隔离测试数据中，各统计合计与数据库查询结果一致；无重复计数。
2. 覆盖跨 UTC 日期、UTC+8 午夜、起止边界、缺失时间桶及空数据。
3. 覆盖一条告警包含多个目标、多类型、改名或已删除摄像头、坏 JSON 及缺失证据图。
4. 新产生的有效告警在正常情况下 10 秒刷新周期内发起更新，并在请求完成后显示。
5. 筛选条件快速切换不出现旧响应覆盖；全屏进入退出保持筛选和图表状态。
6. 真实 USB 摄像头仅启用人员检测时，不因检测到人而虚增告警；若要实测区域入侵，需主人明确选择区域和启用场景。
7. 以隔离的 10 万条历史告警测试查询，目标是在当前机器上常见 30 天查询的 P95 响应时间不超过 1 秒；记录实际结果，超标先分析查询计划。
8. 全屏自动刷新连续运行 30 分钟，不累积定时器、请求和图表实例，不引起分析进程重启；与不开大屏时对比推理耗时，记录实际影响。
9. 现有摄像头导入、人员检测、区域布控、证据查看及告警上报相关回归测试通过。
10. 离线环境可加载页面和所有图表资源；无外部 CDN 依赖。
