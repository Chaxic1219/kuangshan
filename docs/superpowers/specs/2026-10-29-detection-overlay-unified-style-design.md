# 检测选框统一样式设计

日期：2026-10-29  
状态：已批准并已实现  
范围：实时监控大屏、告警处置、告警查询证据中的检测选框颜色与文案

## 1. 背景与问题

同一模型（例如未戴安全帽）在不同界面上的选框表现不一致：

| 位置 | 实现 | 现状颜色 | 现状文案 |
|---|---|---|---|
| 实时监控 | 后端 `annotate_frame` 烧录到 `live.jpg` | 区域内绿 / 区域外橙 | 英文原始 label + 置信度（OpenCV 默认字体难显中文） |
| 告警处置 / 告警查询 | 前端 `DetectionFrame` SVG 叠框 | 报警珊瑚红 / 陪衬青绿 | 中文映射，**无**置信度 |

主人确认目标：同一模型在所有位置使用**同一颜色、同一中文文案**，且文案为汉字。

## 2. 已确认决策

1. **样式基准**：对齐告警处置现有色板（方案 A）。
2. **文案格式**：中文类别名 + 整数置信度百分比，例如 `未戴安全帽 90%`。
3. **不改**模型输出的原始 `label` 字段；只改展示层。
4. **不回刷**历史证据图中已烧录的旧框；新实时流与前端叠框立即按新规则生效。

## 3. 统一展示规则

### 3.1 颜色

| 条件 | 颜色 | 说明 |
|---|---|---|
| `alarmable === true`，或区域入侵场景下 `inRegion === true` 的报警目标 | `#ff8066`（BGR 约 `(102, 128, 255)`） | 报警 / 需关注 |
| 其余检测（陪衬类别、区域外、不可报警） | `#55eac4`（BGR 约 `(196, 234, 85)`） | 跟随绘制、非报警 |

判定优先级建议：

1. 若存在明确的 `alarmable` 字段：以其为准。  
2. 否则：区域类事件用 `inRegion`；无区域信息时默认按报警色（与当前处置台「`inRegion || alarmable` → 珊瑚」一致）。

### 3.2 文案

1. 将 `label` 规范化为小写后查中文映射表。  
2. 映射覆盖至少：人员 / 车辆类、PPE（安全帽 / 未戴安全帽 / 反光衣 / 未穿反光衣 / 口罩等）、烟火、亮度「过暗」「过亮」。  
3. 未命中映射时：若原串已含汉字则原样使用；否则暂时保留原串（可在测试中暴露缺口并补表）。  
4. 若 `confidence` 为有限数值：追加空格与 `round(confidence * 100)` 的百分比，如 ` 90%`。  
5. 所有面向操作员的选框文案必须为汉字类别名（映射表内类别）；禁止再以英文原始类名作为默认展示。

### 3.3 共用语义源

- 前端已有 `frontend_thin/src/components/vision/frame.mjs` 的 `detectionLabel`。  
- 后端新增等价映射与着色助手（建议独立小模块，如 `overlay_style.py`），供 `annotate_frame` 调用。  
- 前后端映射表内容必须保持一致；以规格中的类别列表为验收清单，单测两侧各覆盖关键样例。

不在本期强制「前端从后端 API 拉字典」——优先最小改动保证视觉一致；若后续映射频繁变动，可再抽公共 JSON。

## 4. 改动面

### 4.1 后端

- 文件：`analysis-service/service.py` 中 `annotate_frame`，及新建/抽出的样式助手。  
- 行为：矩形与文字颜色按 §3.1；文字按 §3.2；使用系统可加载的中文字体绘制（macOS / Windows / Linux 各备选路径，找不到字体时降级策略需仍尽量显示中文或明确跳过英文乱码——优先找常见中文字体，如 PingFang / Microsoft YaHei / Noto Sans CJK）。  
- 实时 MJPEG `/live/{id}` 依赖的 `live.jpg` 随分析节奏自动换新样式。

### 4.2 前端

- `DetectionFrame.vue`：框色逻辑与 §3.1 对齐（若已一致则仅核验）；文字改为「中文 + 置信度」。  
- `frame.mjs`：补齐映射与格式化函数（如 `formatDetectionCaption(detection)`），并更新 `frame.test.mjs`。  
- 覆盖页面：实时监控中走 `DetectionFrame` / `AnnotatedLive` 叠框的路径；告警处置；告警查询证据弹窗。后端烧录路径与前端叠框路径均需符合同一规则。

### 4.3 测试

- 后端：`annotate_frame` 对 `no-hardhat` 使用中文文案像素/或可测的 caption 助手纯函数；颜色通道符合报警色。  
- 前端：`detectionLabel` / caption 单测覆盖 `NO-Hardhat` → `未戴安全帽` 及带置信度格式。  
- 手工：live 模式「安全帽测试」监控大屏与告警处置对同一目标观感一致。

## 5. 非目标

- 不修改告警入库 JSON 中的原始 `label`。  
- 不重绘历史 `evidence/*.jpg` 或旧 runtime 截图。  
- 不引入新的设计系统色板扩展（仅统一到现有珊瑚 / 青绿）。  
- 不做按「模型文件」分色；按检测项语义（报警 / 陪衬）分色即可。

## 6. 验收标准

1. 实时监控与告警处置中，同一 `no-hardhat` 目标框色均为 `#ff8066`，文案均为「未戴安全帽」+ 百分比。  
2. PPE 陪衬类（如已戴「安全帽」）为青绿 `#55eac4`，中文文案 + 百分比。  
3. 画面上不再默认出现 `NO-Hardhat` 等英文类名作为操作员可见文案。  
4. 相关单元测试通过；前端构建通过。

## 7. 风险与限制

- OpenCV 中文字体依赖本机字体文件；缺字体环境需有明确降级，并在 README/运维说明中点名推荐字体。  
- 后端烧录与前端叠框仍是两套绘制栈，规则必须靠映射与单测锁死，避免再次漂移。
