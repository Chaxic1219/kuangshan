## 1. 目标与边界

### 1.1 目标

将产品从「本机分析运维控制台」升级为面向企业值班场景的 **安全生产视频智能分析平台**：

1. **企业化**：对齐企业篇手册的值守流程——登录保持在线 → 告警弹窗与声音 → 核实 → 处置/误报 → 查询与考核口径。  
2. **泛用化**：产品叙事与场景配置面向通用安全生产区域（生产区、仓储区、动火区、装卸区等可配置），不绑定矿山或单一行业。  
3. **底层复用**：继续使用现有本机 YOLO/OpenCV 推理、摄像头接入、区域布控、证据落盘与 `frontend_thin` 壳；不重造推理引擎。

### 1.2 成功标准（总览）

- 值班员可按手册流程完成「发现 → 处置」闭环，而无需进入视频配置页。  
- 告警具备明确处置状态，支持按状态/级别/位置/时间查询，证据含图片线索（视频线索在能力具备时提供）。  
- 菜单与文案呈现企业安全产品，而非纯运维工具；运维能力仍保留给管理员/实施人员。  
- 不引入虚假业务数据；统计来自真实告警与处置记录。

### 1.3 非目标

- 不建设上级监管多企业门户、跨企业排名大盘（手册中的「对企业排名」若需，仅在单机/单租户内做本企业统计；跨企业监管另立项）。  
- 本期不实施 License / 公网授权服务（规格已留档，主路径稳定后再接）。  
- 不一次完成多租户 SaaS、云端集中推理、移动 App。  
- 不替换 MediaMTX / Ultralytics 主链路；不加壳。

## 2. 产品定位与角色

| 角色 | 典型用户 | 主要界面 |
|---|---|---|
| 值班员 | 企业安全值班 / 中控 | 监控总览、告警处置、告警查询 |
| 运维实施 | 我方或客户 IT | 视频管理、场景模型、实时监控细调 |

## 4. 告警处置域模型（E1 核心）

### 4.1 状态机

```text
pending（未处置）
    ├── handled（已处置）
    └── false_positive（误报）
```

- 新产生告警默认为 `pending`。  
- 处置时记录 `handled_at`、`handled_by`（E3 前可用本地用户名或固定值班账号）、可选备注。  
- **处置率** = 已离开 `pending` 的数量 / 周期内总告警数。  
- **处置时长** = `handled_at - created_at`，对周期内已处置告警取平均（E4 展示）。

### 4.2 风险级别

映射现有场景/事件到手册中的高 / 中 / 低（可配置表）。处置台默认按风险从高到低排列未处置告警。

### 4.3 线索

- **图片线索**：沿用现有证据图。  
- **视频线索**：若本机已有片段或可裁剪预览则提供；否则 E1 可先做图片 +「暂无视频片段」占位，E1.1 再补。

### 4.4 交互（对照手册 4.3～4.4）

1. 存在新告警或未处置告警时：弹窗提示数量与最高风险级别，并播放提示音（可设置静音）。  
2. 进入处置台：逐条查看详情与线索；操作「处置完成」或「误报」。  
3. 自动跳转下一条，直至无 `pending`，弹窗关闭。  
4. 告警查询：筛选摄像头位置、状态、级别、时间；卡片进详情。

### 4.5 数据与 API 原则

- 在现有告警/事件存储上扩展字段（状态、处置时间等），避免平行假库。  
- 新增只读/写处置 API，仍受本机控制台令牌（及日后真实登录会话）约束。  
- 导出 CSV 可增加处置状态列（E1 或紧随）。

## 5. 分期计划

| 阶段 | 名称 | 范围 | 主要验收 |
|---|---|---|---|
| **E1** | 告警处置闭环 | 状态机、弹窗与声音、处置台、查询筛选、图片线索 | 对照手册 4.3、4.4 可走通 |
| **E2** | 值班总览 | 近 7 日统计、高风险数、类型饼图、紧急联系人 CRUD | 对照手册 4.2 |

| **E4** | 考核口径 | 处置率、平均处置时长；本企业内展示 | 对照手册 3.3 指标定义 |

每阶段单独写实施计划与测试；禁止跨阶段大爆炸提交。

## 6. 技术约束

- 前端继续 `frontend_thin`（Pure Admin thin + 业务模块 `vision`）。  
- 后端继续 `analysis-service` HTTP 控制台；告警扩展优先落在现有 alerts/events/SQLite 路径。  
- 浏览器：Chrome / 国产极速内核；不承诺 IE。  
- 建议部署于 7×24 值班室环境（文档声明，非代码强制）。

## 7. 泛用化原则

- 场景与模型保持可配置目录，不写死矿山事件名称为唯一卖点。  
- 演示数据与文案使用中性安全场景用语。  
- 区域类型（生产/仓储/动火/装卸）可作为摄像头「位置/分区」标签，服务于查询与总览，而非独立产品线。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 处置状态与旧「仅记录事件」混淆 | 明确字段与迁移：旧数据视为 `pending` 或只读历史策略在 E1 计划中写死 |
| 弹窗打扰运维调试 | 提供静音/勿扰；运维角色可关闭弹窗 |
| 视频线索缺失 | E1 不阻塞；文档标明能力级 |
| 与 License 闸门未来冲突 | 闸门挂在启停分析；处置读写作会话鉴权，预留接口 |
