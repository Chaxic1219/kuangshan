# 视联洞察 · 标准部署与 License 授权设计

日期：2026-10-28  
状态：待主人审阅规格  
产品：视联洞察（VISION INSIGHT）  
已确认：

- 授权形态：混合（首次联网激活绑定机器 → 日常可离线 → 到期续期）
- 网络：客户出网 HTTPS 白名单至自建授权域名
- 授权服务：我方自建（非第三方 License 平台）
- 硬件交付基线：标准档 3～6 路并发分析
- 实现路线：应用层 License 闸门（方案 1）；不加壳、不做一体机本期范围

## 1. 目标与边界

### 1.1 目标

1. 给出可对外交付的**标准部署规范**（硬件、网络、安装、验收、运维）。
2. 引入 **License 验证**：换机须重新向我方申请；可控制授权到期时间与并发路数；抑制整盘拷贝到另一台电脑即用。
3. 与现有本机架构兼容：Python 控制台、MediaMTX、YOLO 分析、`frontend_thin` 托管，不改为云端多租户推理。

### 1.2 非目标（本期）

- PyArmor / 商业加壳、硬件加密狗、整机镜像出厂。
- 把模型权重做成「无 License 完全无法读盘」（成本高，另立项）。
- Linux 生产交付打磨（可预留；标准交付仍以 Windows / macOS 为主）。
- 公网暴露分析控制台；默认仍本机或内网访问。
- 完整多租户 SaaS 计费门户（先做签约客户台账 + 签发/吊销）。

## 2. 标准硬件与网络（交付基线）

### 2.1 硬件（3～6 路 CPU 推理）

| 项 | 最低 | 推荐 |
|---|---|---|
| CPU | 6 核（x64 或 Apple Silicon） | 8 核及以上 |
| 内存 | 16 GB | 32 GB |
| 系统盘 | 256 GB SSD | 512 GB SSD |
| 数据可用空间 | ≥ 50 GB | ≥ 100 GB |
| GPU | 不要求 | 可选，加速另案 |
| 摄像头 | USB / 内置 / 局域网 RTSP | 多路 USB 建议分散控制器 |
| 操作系统 | Windows 10/11 或 macOS 12+ | 与现行交付一致 |

经验值：单路分析约 350～400 MB 内存；进程并发上限默认 6，实际生效为  
`min(环境变量上限, License.max_running)`。

入门档（1～2 路）与增强档（7～16 路）不在本期标准交付文档展开，后续可增补附录。

### 2.2 网络

| 用途 | 要求 |
|---|---|
| 本机服务 | `127.0.0.1:8765` 控制台；`8560` RTSP；`8889` WebRTC；`9997` MediaMTX API |
| 出网 | 允许 HTTPS 访问我方授权域名（示例 `https://license.<domain>`），可防火墙白名单 |
| 摄像头网 | 局域网 IPC 时分析机须能访问其 RTSP；摄像头无需上公网 |
| 访问面 | 默认控制台仅本机；若需同网段浏览器访问，由客户内网策略单独放开，**不**默认对公网开放 |

演示流（`lite`/`full`）与本机摄像头（`live`）共用 MediaMTX，同时仅一种模式；部署文档须写明现场默认模式建议（生产多用真实 RTSP 或 `live`，演示用 `lite`）。

## 3. License 模型

### 3.1 机器指纹（machine_id）

客户端在本机计算稳定指纹，不把原始硬件序列写入业务日志：

- Windows：平台/主板 UUID +（可选）系统盘卷序列  
- macOS：Hardware UUID +（可选）系统盘标识  
- 混入产品盐（仅客户端与签发策略约定的常量）  
- 输出：规范化后的短哈希（如 32 hex）作为 `machine_id`

整盘拷贝到另一台电脑后 `machine_id` 变化；旧 License 即使文件被复制，绑定校验失败。

### 3.2 License 文件字段

由我方**私钥**签名；客户端只内置**公钥**验签。建议字段：

| 字段 | 含义 |
|---|---|
| `license_id` | 全局唯一授权号 |
| `customer` | 客户标识 |
| `product` | 产品标识（如 `vision-insight`） |
| `machine_id` | 绑定指纹 |
| `not_before` / `not_after` | 生效/到期（UTC） |
| `max_running` | 最大并发分析路数 |
| `features` | 可选功能开关（预留） |
| `issued_at` | 签发时间 |
| `signature` | Ed25519 或 RSA-SHA256 签名 |

本地路径建议：`analysis-service/data/license.lic`（或独立 `license/license.lic`），文件权限限制为运行用户可读。

### 3.3 生命周期（混合）

1. **首次激活**：界面输入客户码/激活码 → HTTPS `POST /v1/activate` 提交 `{machine_id, product, customer_code}` → 服务端校验后签发 → 写入本地 License。  
2. **日常运行**：启动与写操作做本地验签 + 指纹一致 + 未过期；**不要求**每次联网。  
3. **续期**：到期前 N 天（建议 14 天）提示；优先联网 `POST /v1/renew`；若现场临时无法出网，支持导入我方签发的续期文件。  
4. **换机**：新机重新激活；服务端吊销旧 `license_id`；按需迁移 `data/` 配置与证据，**不**迁移旧 License。  
5. **宽限期**：时钟异常或续期短暂失败时，允许短宽限（建议 **72 小时**）；超时后拒绝启动新分析（可保留只读提示/已有只读页面，策略在实现计划中固定）。

### 3.4 闸门位置（应用层）

| 位置 | 行为 |
|---|---|
| `start.py` / 控制台启动 | 无有效 License：不得进入可分析就绪态（明确错误提示） |
| `Controller.start` 及关键写接口 | 再次校验；过期/指纹不匹配返回 403 类错误 |
| 并发路数 | `min(配置上限, license.max_running)` |

试用：通过短 `not_after` + 客户码发放，不另做无限试用旁路。

### 3.5 安全底线与诚实边界

- 私钥仅存授权服务器；客户端无私钥。  
- 激活/续期接口：限流、客户码绑定、审计日志。  
- **诚实说明**：应用层闸门可防「普通用户整盘拷贝」与过期滥用；不能从密码学上杜绝专业逆向。规模盗版靠签发台账、吊销、合同与审计抑制。加壳为后续增强项。

## 4. 自建授权服务

### 4.1 组件

- **管理端**：创建客户、发放激活码、设定/修改到期日与路数、吊销、查看机器绑定与审计。  
- **API**：`/v1/activate`、`/v1/renew`；可选 `/v1/revoke-check` 或续期时下发吊销状态。  
- **数据**：客户、激活码、机器、`license_id`、状态、操作审计。  
- **部署**：公网 HTTPS；管理端强制强认证（建议双因素或仅 VPN）。

### 4.2 与分析产品的关系

授权服务**独立仓库/独立进程**，不嵌入客户分析机。分析机只做：指纹、激活/续期客户端、本地验签闸门。

## 5. 客户现场交付流程

1. 硬件与系统验收（第 2 节表）。  
2. 安装：Python 环境、依赖、MediaMTX/FFmpeg、`frontend_thin/dist`、启动脚本。  
3. 网络：本机端口；出网白名单到授权域名。  
4. 首次激活写入 License。  
5. 配置视频源与场景；冒烟：启停至少 1 路、封面/事件可见。  
6. 交付运维说明：启停、`lite`/`live` 区别、续期、换机、日志与数据目录。

### 5.1 交付物

- 安装包或安装文档（版本号、构建哈希）  
- 客户码/激活说明  
- 《部署验收清单》《运维手册》  
- 不包含我方私钥、授权服务源码（除非合同另约）

## 6. 实施分期（供后续计划拆解）

| 阶段 | 内容 |
|---|---|
| P0 | 本地 License 文件格式 + 公钥验签 + 指纹 + 启动/启停闸门 + 路数上限 |
| P1 | 自建激活/续期 API + 简易管理台 + 客户端激活页 |
| P2 | 宽限期、到期提醒、吊销、离线续期文件、部署文档定稿 |
| 后续 | 可选加壳、增强档硬件附录、Linux 交付 |

## 7. 验收标准

1. 无 License 或指纹不匹配：不能启动分析。  
2. 过期且过宽限期：不能启动分析；提示联系供应商。  
3. 拷贝 `license.lic` 到另一台机器：不能通过绑定校验。  
4. 有效 License：标准档机器可按授权路数运行；出网激活/续期成功。  
5. 部署文档含硬件、网络白名单、激活与换机步骤，可按清单验收。
